# ATLAS — Intelligent Banking Decision Support System

ATLAS is a reproducible intelligent banking decision-support system demonstrating retail and enterprise banking methodology. It combines population-aware behavioral segmentation, temporal forecasting, product propensity modeling, ontology-based eligibility and recommendation rules, retrieval-augmented generation, LangGraph orchestration, and a Django dashboard.

This portfolio edition contains source code, methodology, tests, and small synthetic demonstration resources only. It retains nine catalogue-level product examples from the approved canonical catalogue, with confidential attributes and internal rules removed. It does not contain bank data, credentials, database exports, trained model binaries, vector stores, private reports, or operational synchronization tools.

## Architecture

```tex
synthetic data -> segmentation -> forecasting / propensity
                         \-> ontology + hybrid recommendations
public documents -> RAG service -> LangGraph assistan
                         \-> Django dashboard and API
```

## Main capabilities and technical stack

- Django dashboard and authenticated customer-context views.
- FastAPI retrieval service with grounded public answers.
- LangGraph routing for public information, customer analytics, recommendations, and unsupported actions.
- Behavioral segmentation, forecasting, propensity scoring, ontology eligibility, and hybrid recommendations.
- Python, Django, FastAPI, LangGraph, pandas/Polars, scikit-learn-compatible model contracts, RDF/OWL, PostgreSQL-compatible schemas, and Ollama-compatible local generation.

## Machine-learning methodology

The retained implementation prepares customer features, evaluates static behavioral segments, separates static segment forecasts from temporal customer outlooks, trains propensity models with explicit feature-order contracts, and combines propensity candidates with ontology prerequisites, alternatives, conflicts, eligibility, and ownership exclusion. The demonstration uses bounded synthetic fixtures and does not include fitted binary models.

## Original research results versus demonstration results

The original ATLAS research and operational verification recorded 932,554 recommendations for recommendation run 18: 407,862 propensity-backed and 524,692 ontology-only. Those figures describe the full original catalogue and are provided as research context only; they are not generated by this repository.

Approved original evaluation metrics, retained here as aggregate research context, include Retail GMM (k=5) silhouette 0.4355, Davies–Bouldin 0.9494, and Calinski–Harabasz 14,279.44; Enterprise GMM (k=6) silhouette 0.4229, Davies–Bouldin 0.8422, and Calinski–Harabasz 3,429.65; and product-propensity holdout averages across 77 finite product evaluations of ROC-AUC 0.5972 and average precision 0.2721. These metrics describe the original full-catalogue experiments and are not claims about the reduced demonstration.

This portfolio edition contains a reduced nine-product catalogue, eight ownership fixture rows, and eight recommendation fixture rows. These are demonstration results for exercising the architecture and ontology rules and must not be compared numerically with the original research results.

## Installation

Use Python 3.11 with the pinned dependencies:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.tx
Copy-Item .env.example .env
```

The demonstration uses a reduced nine-product catalogue and fictional local customer data. No production or bank database is required. See `docs/DEMO_CATALOGUE.md` for the retained products and relationship coverage.

## Demonstration

1. Build a small synthetic customer/product dataset with the data-generation module.
2. Run the bounded segmentation, forecasting, propensity, and recommendation examples.
3. Start the RAG API and Django dashboard using the local development commands in `docs/DEMO.md`.
4. Run the essential unit tests before presenting the project.

The full-scale research artifacts and operational PostgreSQL synchronization workflow are intentionally excluded from this edition.

## Research scope and limitations

- Propensity labels are synthetic ownership-profile labels, not observed conversions.
- Forecasts are group or customer-outlook demonstrations, not financial advice.
- The original project’s fitted segmentation estimators were not available as portable binaries; segmentation source code and methodology are retained, with inference reproduced from synthetic demo resources.
- LLM calls require a separately configured local Ollama model; deterministic routing and policy tests do not require Ollama.
